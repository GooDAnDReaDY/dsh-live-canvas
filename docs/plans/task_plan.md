# Техническое задание и план реализации: dsh-live-canvas

## 1. Цели и назначение
Предоставление встроенного в браузер интерактивного холста (Live Preview Canvas) для рендеринга генерируемых агентом веб-страниц, React-компонентов, SVG-графики и диаграмм Mermaid с поддержкой мгновенного hot-reload и инспектора элементов.

## 2. Архитектура решения
- **Серверный роут `PreviewServer`**: регистрируется через `ctx.webServer` и отдает изолированную песочницу со строгой политикой CSP.
- **Модуль `HotReloadWatcher`**: отслеживает запись файлов в рабочей сессии и рассылает SSE-события в iframe.
- **Браузерная панель `LiveCanvasContainer`**: монтируется в UI-слот рабочей области DSH, поддерживает переключение разрешений и инспекцию DOM.

## 3. Декомпозиция задач (Work Breakdown Structure)
- [ ] **Этап 1: Сервер статики и песочница (Backend Sandbox)**
  - [ ] 1.1 Роут `GET /plugins/dsh-live-canvas/sandbox/*` с изолированным origin и sandbox-заголовками.
  - [ ] 1.2 SSE endpoint `GET /plugins/dsh-live-canvas/events` для рассылки уведомлений об изменениях файлов.
  - [ ] 1.3 Сборщик бандлов на лету для React/Vue/SVG компонентов.
- [ ] **Этап 2: Инструменты агента (Agent Tools)**
  - [ ] 2.1 Тул `live_canvas_preview_url` (получение активной ссылки на предпросмотр).
  - [ ] 2.2 Тул `live_canvas_emit_update` (ручной триггер обновления холста).
  - [ ] 2.3 Тул `live_canvas_inspect_element` (чтение выделенного пользователем узла).
- [ ] **Этап 3: Клиентский интерфейс (Frontend Web UI)**
  - [ ] 3.1 Контейнер Live Canvas со сплит-панелью и переключателем вкладок.
  - [ ] 3.2 Тулбар управления (Mobile / Tablet / Desktop / Fullscreen, Refresh, Open in tab).
  - [ ] 3.3 Двусторонний `postMessage` мост для клика по элементу -> отправка селектора агенту.
  - [ ] 3.4 Карточка настроек `settings.plugin.item`.
- [ ] **Этап 4: Тестирование и безопасность**
  - [ ] 4.1 Проверка изоляции скриптов внутри sandbox iframe.
  - [ ] 4.2 Тесты корректности отдачи MIME-типов и SSE-потока.
  - [ ] 4.3 `npm test` без сети и внешних зависимостей.
